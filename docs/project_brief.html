XIAO EN KL BERHAD · AGENT RELATIONS Internal project brief · Phase 1

Agent Commission Tool

Replacing the twice-monthly manual Excel commission process with a web-based ledger that remembers contract state between cycles — so nothing has to be cross-checked by eye, and every payout has a written reason.

Business rules confirmed against real export data Data model drafted & reviewed Build starting
Why

The problem with the current process

Today

Twice a month, someone opens the Kenjin export and a separate payment list, and manually checks — per contract — whether installment 1 or installment 6 was just paid since the last check. Nothing remembers this between cycles; it's re-derived by eye, every time.

The risk

A missed row means an agent doesn't get paid on time. A double-counted row means Accounts pays commission twice. Because state isn't tracked anywhere, an error is silent until someone notices — usually the agent.

Approach

What the tool actually does

A private internal site, not a public app. The existing workflow stays the same on both ends — Kenjin export in, Excel report out — but a real database sits in the middle as the single source of truth for what's already been paid.

Upload

The same Kenjin Master report your team already generates, uploaded through a login — not a shared password.

Download

An Excel file listing exactly what's newly due this cycle, formatted for Accounts — the manual cross-check is gone, not the Excel handoff.

Rules encoded

Commission logic, Phase 1

TriggerRateCondition
Full payment 15% Released 5 days after the customer's full-settlement date (Pre-Need). At-Need contracts skip this wait but require an inurnment date on file.
Installment 1 paid 7.5% Always installment #1, regardless of whether the plan runs 6, 12, 18, or 24 months.
Installment 6 paid 7.5% Always installment #6, same rule — never the plan's final installment.

A contract on hold (incomplete documents) or marked cancelled / withdrawn is excluded from every run until that status changes.

Contract lifecycle

How a contract's state is tracked

If nothing new was crossed since the last upload, nothing happens — the contract carries forward silently. That silence is the point: no flag, no re-review, no manual memory required.

Accountability

Every payout has a written reason

Individual logins, not a shared password — every upload and every commission run is tied to whoever processed it. Every time a commission becomes due, the system writes down what triggered it and when, so "why was this paid" has a factual answer instead of a reconstruction from old spreadsheets.
